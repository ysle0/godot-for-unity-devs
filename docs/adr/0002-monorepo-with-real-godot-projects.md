# 스니펫과 샘플을 실제 Godot 프로젝트로 두는 모노레포

## 결정

- **하나의 저장소**: pnpm 워크스페이스 모노레포 안에 사이트(`site/`, Astro + Starlight)와 코드 파일을 함께 둔다.
  - `godot/snippets/`: 개념 스니펫용 Godot 프로젝트 하나
  - `godot/sample/<NN-모듈>/`: 샘플 스냅샷마다 Godot 프로젝트 하나
  - `unity/`: 설명용 Unity C# 파일
- **파일에서 발췌**: 챕터의 코드는 MDX에 직접 쓰지 않는다. 이 파일들에서 `#region` 단위로 발췌해 보여준다.
- **이유**: 검증된 코드(GDScript, Godot C#)가 모두 CI의 파싱·빌드 검사를 거치게 하려는 것이다. 문서 속 코드가 엔진 버전과 어긋나지 않게 한다.

## 샘플 스냅샷의 형태

샘플 스냅샷은 Git 태그가 아니라 모듈별 폴더로 둔다. 각 폴더는 `project.godot`를 가진 독립 Godot 프로젝트다.

**폴더를 고른 이유**: 중복은 생기지만 세 가지를 얻는다.
- 모든 단계를 CI가 한 번에 검사할 수 있다.
- 앞 단계를 고쳐도 태그를 다시 찍을 필요가 없다.
- 독자는 폴더 하나만 열면 된다.

**프로젝트 하나로 합치지 않은 이유**: 합의(Q17)는 "`godot/`는 Godot 프로젝트 1개"였다. 하지만 두 가지 문제가 있어 작성 중에 고쳤고, 저장소 주인이 확인했다(Q28).
- 한 Godot 프로젝트 안에서는 스냅샷마다 같은 `class_name`(예: `Player`)이 겹친다.
- 하위 폴더는 독자가 프로젝트로 열 수 없다.

## Consequences

- **`?raw` import 설정**: `site/`가 자기 루트 밖의 `godot/`, `unity/` 파일을 `?raw`로 import하려면 워크스페이스 루트 인식이나 `vite.server.fs.allow` 설정이 필요할 수 있다. 첫 스파이크에서 확인한다.
- **배포 방식**: `withastro/action`은 `path` 폴더 안에서만 lockfile을 찾는다. 워크스페이스 루트에 lockfile이 있으면 직접 빌드하고 `actions/deploy-pages`로 배포해야 할 수 있다.
- **스니펫 이름 규칙**: `godot/snippets/`는 프로젝트 하나라서 이름이 겹치면 안 된다.
  - GDScript: `class_name`이 서로 겹치지 않게 한다.
  - Godot C#: 스니펫을 모듈별 네임스페이스에 넣는다. Godot C# 클래스는 `partial`이라서 같은 네임스페이스의 같은 이름 클래스가 하나로 합쳐지고, 멤버 중복으로 빌드가 깨진다.
